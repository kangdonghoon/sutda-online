# 섯다 온라인

친구들과 링크 하나로 같이 하는 2장 섯다와 텍사스 홀덤이에요. 칩은 가짜예요. 두 게임은 같은 계정 칩을 같이 써요.

- **서버가 딜러**: 셔플, 패 보관, 족보 판정을 모두 서버가 해요. 각 플레이어는 자기 패만 받아요.
- **계정**: 아이디·비밀번호로 가입해요. 칩, 판수, 승수, 최고 판돈이 DB에 저장돼요.
- **관리자 페이지**: `/admin`에서 회원 칩 수정, 계정 정지, 열린 방 닫기를 할 수 있어요.

## 구성

```
server.js            HTTP 서버 · 계정/세션 · 방 관리 · 게임 루프 · SSE 푸시 · 관리자 API
store.js             저장소 (DATABASE_URL 있으면 Postgres, 없으면 메모리)
public/core.js       섯다 규칙 엔진 (서버·브라우저 공용)
public/holdem.js     홀덤 규칙 엔진 (서버·브라우저 공용, 섯다 엔진과 같은 함수 이름)
public/index.html    게임 화면
public/style.css     테마 (장판·담요·한지)
public/cards.js      화투 카드 SVG
public/fx.js         연출 (카드·칩 날리기, 승리 효과, 효과음, 베팅 음성)
public/app.js        게임 클라이언트
public/admin.html    관리자 페이지
test/                규칙 엔진·저장소 테스트
```

## 배포: Render + Neon

### 1. Neon에서 DB 만들기
1. neon.com에 가입해요. GitHub 로그인이면 돼요.
2. **New Project**를 만들어요.
   - 이름: 아무거나 (예: `sutda`)
   - Region: **AWS Asia Pacific (Singapore)**. Render를 싱가포르로 했다면 같은 곳이 빨라요.
3. 프로젝트 대시보드에서 **Connect**를 누르고 연결 문자열을 복사해요. 이렇게 생겼어요.
   ```
   postgresql://neondb_owner:비밀번호@ep-xxxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
   이 문자열에는 비밀번호가 들어 있어요. **GitHub에 올리거나 남에게 보여주지 마세요.**

### 2. Render에 환경변수 넣기
Render 서비스 화면 → **Environment** → **Add Environment Variable**에서 두 개를 넣어요.

| Key | Value |
|---|---|
| `DATABASE_URL` | Neon에서 복사한 연결 문자열 |
| `ADMIN_USERS` | 관리자로 쓸 **아이디**. 여러 명이면 쉼표로 (예: `donghun,minsu`) |

저장하면 Render가 다시 배포해요. 테이블(`users`, `sessions`)은 서버가 시작할 때 자동으로 만들어져요.

Render 설정은 **Language: Node**, **Build Command: `npm install`**, **Start Command: `npm start`**여야 해요. `pg` 패키지를 설치해야 하기 때문이에요.

### 3. 확인
- 로그에 `섯다 서버 실행 중 ... (저장소: postgres, 관리자: donghun)`이 보이면 성공이에요.
- `https://<주소>/healthz`가 `"db":"postgres"`를 보여줘야 해요. `"memory"`로 나오면 `DATABASE_URL`이 안 들어간 거예요.
- 사이트에서 `ADMIN_USERS`에 적은 아이디로 가입하면, 입장 화면에 **관리자** 버튼이 생겨요.

`DB 연결 실패`가 뜨고 서버가 꺼지면 연결 문자열이 틀린 거예요. 앞뒤 공백이나 따옴표가 들어가지 않았는지 확인하세요.

## 로컬 실행

```bash
npm install
node server.js                                  # DB 없이: 메모리 저장 (끄면 사라짐)
DATABASE_URL="postgresql://..." ADMIN_USERS=donghun node server.js   # Neon에 연결
```

Windows PowerShell에서는 이렇게 해요.
```powershell
$env:DATABASE_URL="postgresql://..."; $env:ADMIN_USERS="donghun"; node server.js
```

## 노는 법
1. 회원가입이나 로그인을 해요.
2. **방 만들기**를 누르고 **초대 링크 복사**로 링크를 친구에게 보내요.
3. 친구가 링크를 열면, 로그인하거나 가입하자마자 그 방으로 들어와요.
4. 방장이 **게임 시작**을 누르면 시작이에요. 판돈, 진행 방식, 땡값은 방을 만들 때 정해요. 사람이 모자라면 **봇 추가**로 채울 수 있어요.

칩이 필요하면 **칩 충전**으로 관리자에게 요청해요 (아래 "칩 충전 요청" 참고).

## 화면과 소리

- **휴대폰은 가로로만**: 게임 화면에서 세로로 들면 "가로로 돌려주세요" 안내가 덮어요. 안드로이드는 [전체 화면으로 가로 고정] 버튼(또는 상단 ⛶)으로 가로 고정까지 돼요. 아이폰은 브라우저가 고정을 막아서 직접 돌려야 해요. 로그인·방 목록은 세로로도 써요.
- 가로 폰에서는 방장 버튼(시작·봇 추가·자동)이 상단바로 올라가요.
- **채팅창 닫기**: 상단 [채팅] 버튼. 닫혀 있을 때 새 메시지가 오면 숫자가 뜨고 화면 위에 잠깐 보여요. 상태는 브라우저에 기억돼요.
- **베팅 음성**: 누가 다이·체크·콜·삥·하프·따당을 하면 브라우저 내장 한국어 음성(TTS)으로 불러줘요. 사람마다 목소리 높낮이가 달라요. 🔊 버튼으로 효과음+음성 → 효과음만(🔉) → 끔(🔇). 기기에 한국어 음성이 없으면 소리가 안 날 수 있어요.

## 봇 연습
**봇이랑 연습**으로 만든 방은 연습방이에요.
- **연습 칩 10,000**으로 해요. 따거나 잃어도 계정 칩은 그대로예요.
- 연습 칩이 판돈보다 적어지면 **연습 칩 충전**으로 관리자 승인 없이 바로 다시 받아요.
- 방 목록에 보이지 않고, 다른 사람은 들어올 수 없어요.
- 수수료를 떼지 않고, DB에 아무것도 저장하지 않아요. 나가면 방이 바로 사라져요.

## 방 규칙 (진행 방식과 땡값)
방을 만들 때 **판돈, 진행 방식, 땡값, 동점 처리**를 정해요. 방을 만든 뒤에는 바꿀 수 없어요. 마지막으로 고른 값은 다음에 방을 만들 때 기본으로 선택돼요. 방 목록과 대기 화면에 그 방의 규칙이 보여요.
- **한 장씩 · 2번 베팅** (기본): 한 장 받고 베팅, 한 장 더 받고 베팅
- **두 장 받고 · 1번 베팅**: 두 장을 다 받고 한 번만 베팅. 구사 재경기 때도 두 장씩 다시 돌려요.
- **패가 같을 때** (기본: 재경기): 패를 열었을 때 가장 높은 패가 동점이면, 판돈을 그대로 두고 **동점인 사람끼리만** 새로 패를 받아 다시 겨뤄요.
  - 동점보다 낮은 사람은 그 판에서 진 거라 빠져요(패배).
  - 동점자들이 받을 수 없는 초과 베팅은 재경기 전에 정산해요.
  - 진행 방식은 방 규칙대로예요.
  - 동점이 3번 이어지면 그다음엔 나눠 가져요.
  - **나눠 갖기**를 고르면 예전처럼 바로 나눠요.
- **구사 재경기 때 다이한 사람 재참가**: 구사나 멍텅구리구사로 재경기가 되면, 그 판에서 다이했던 사람에게 참가 여부를 물어요(12초).
  - 참가하면 끝까지 남은 사람이 이번 판에 건 금액과 같아지도록 차액을 내고 들어와요. 칩이 모자라면 올인이에요.
  - 대답하지 않거나 자리를 비운 사람은 불참으로 처리돼요. 봇은 알아서 정해요.
  - 모두 대답하면 바로 재경기를 시작해요.
- **땡값** (있음/없음): 장땡이나 광땡으로 이기면, **끝까지 남은 다른 사람**(다이한 사람 제외)이 판돈과 별도로 1인당 내요. 금액은 그 방의 기본 판돈 기준이에요.
  - 장땡: 판돈의 100%
  - 13·18광땡: 판돈의 150%
  - 38광땡: 판돈의 200%
  - 1~9땡은 땡값이 없어요.
  - 땡잡이·암행어사에게 잡힌 경우와 모두 다이로 끝난 판도 땡값이 없어요.
  - 칩이 모자라면 가진 만큼만 내요.

## 텍사스 홀덤
방 만들기 창에서 **게임: 텍사스 홀덤**을 고르면 돼요. 봇 연습도 홀덤으로 할 수 있어요.
- **인원**: 2~6명.
- **블라인드**: 50/100, 250/500, 500/1,000, 2,500/5,000 중에서 골라요. 딜러 버튼(D)은 판마다 한 칸씩 돌고, 그 왼쪽 두 사람이 스몰(SB)·빅(BB) 블라인드를 내요. 둘이 할 때는 딜러가 스몰 블라인드예요.
- **베팅 방식**: 노리밋(가진 칩까지) 또는 팟리밋(한 번에 판돈 크기까지). 방 만들 때 정해요.
- **진행**: 패 2장 → 프리플롭 베팅 → 플롭 3장 → 턴 1장 → 리버 1장, 매번 베팅. 남은 사람끼리 패 2장 + 공용 카드 5장 중 가장 좋은 5장으로 겨뤄요. 같으면 나눠 가져요.
- **레이즈**: 최소는 빅 블라인드 또는 직전에 올린 크기만큼. 덜 올린 올인은 이미 행동한 사람에게 다시 올릴 권리를 주지 않아요. 올인하면 사이드팟으로 나눠요.
- **버튼**: 폴드 · 체크/콜 · 올인 · ½팟 · 팟 · 레이즈(금액 직접 고르기: 슬라이더, 최소·½팟·¾팟·팟·올인).
- **수수료**: 섯다와 같은 관리자 설정을 써요. 플롭이 안 열린 판은 안 떼요(노 플롭 노 드롭).
- 관리자 페이지의 딜 옵션은 섯다 방에만 있어요.

## 칩 충전 요청
칩 충전은 관리자 승인 방식이에요.
1. 플레이어가 **칩 충전**을 누르고 금액(1만·3만·5만·10만)을 고른 뒤, 원하면 메모를 남겨 요청해요. 게임 화면 위쪽이나 입장 화면 프로필에 있어요.
2. 관리자 페이지 맨 위 **칩 요청**에 바로 떠요. 브라우저 탭 제목에도 `(1) 섯다 관리자`처럼 대기 수가 보여요.
3. 관리자는 **지급할 칩**을 고쳐서 **승인**하거나 **거절**해요.
4. 승인하면 칩이 바로 들어가요. 그 사람이 진행 중인 판에 살아 있으면 **그 판이 끝난 뒤** 들어가요. 결과는 플레이어에게 알림으로 떠요.

그 밖의 규칙이에요.
- 대기 중인 요청은 한 사람당 하나예요. 플레이어가 직접 취소할 수 있어요.
- 처리 내역은 DB `chip_requests` 테이블에 남고, 관리자 페이지 **최근 처리 내역**에서 볼 수 있어요.
- 받은 충전 칩 총액은 회원별로 기록돼요 (`users.bought`). 예전 자동 충전분은 1회당 10,000으로 이전돼요.

## 칩 반납 요청
충전의 반대예요. 칩을 관리자에게 돌려줄 때 써요. 게임 칩은 돈 가치가 없어요.
1. 플레이어가 **칩 충전·반납** 창에서 **반납 요청** 탭을 고르고, 반납할 칩(100 이상, 가진 칩 이하)을 적어 보내요. **전부** 버튼도 있어요.
2. 보내는 순간 그만큼 보유 칩에서 **따로 떼어 둬요**. 화면에는 `보유 7,000 · 반납 대기 3,000`처럼 보이고, 떼어 둔 칩은 베팅에 못 써요.
   판 진행 중에 보내면 그 판이 끝날 때 남은 칩에서 떼어 둬요.
3. 관리자 페이지 **칩 요청** 목록에 `반납` 표시와 **떼어 둔 칩**이 보여요. **회수할 칩**을 확인하고 **회수**하거나 **거절**해요.
4. 회수하면 떼어 둔 칩이 사라져요. 일부만 회수하면 나머지는 돌려줘요. 거절하거나 본인이 취소하면 떼어 둔 칩이 전부 돌아와요.

충전과 반납을 합쳐 대기 중인 요청은 한 사람당 하나예요. 떼어 둔 칩은 DB `chip_requests.held`에, 반납 총액은 `users.returned`에 기록돼요 (관리자 회원 목록의 충전 칸 아래).

## 수수료
판이 끝날 때 판돈에서 일정 비율을 떼요. **플레이어 화면에는 표시되지 않고**, 관리자 페이지(`/admin`)의 **수수료** 섹션에서만 설정하고 통계를 볼 수 있어요. 승자에게는 수수료를 뺀 금액이 표시돼요.
- **기본값**: 5%, 최대 2,000, 최소 판돈 500, 모두 다이로 끝난 판은 제외
- **계산 기준**: 아무도 받지 않은 초과 베팅은 돌려주고, 실제로 겨룬 판돈에서만 떼요. 사이드팟이 있으면 팟 크기에 비례해서 나눠 떼요.
- **재경기(구사)**: 재경기가 되는 판에서는 떼지 않고, 최종 결과가 나올 때 한 번만 떼요.
- **설정 변경**: 바꾼 설정은 각 방의 다음 판부터 적용돼요. DB `settings` 테이블에 저장돼서 서버를 재시작해도 유지돼요.
- **기록**: 수수료를 뗀 판은 DB `rake_log` 테이블에 기록돼요. 관리자 페이지에서는 오늘(한국 시간), 최근 7일, 전체 합계만 보여요.

## 동작 규칙
- **칩 저장 시점**: 판이 끝날 때, 방에서 나갈 때, 충전할 때, 관리자가 수정할 때 저장돼요.
- **한 계정은 한 방에만** 앉을 수 있어요. 다른 방에 들어가면 이전 방에서 자동으로 빠져요. 이전 방에서 판이 진행 중이면 그 판이 끝난 뒤에 옮길 수 있어요.
- **판 도중에 나가면** 내 차례일 땐 바로 다이 처리되고, 그 판이 끝나면 자리에서 빠져요.
- **관리자가 칩을 바꾸는 건** 그 사람이 진행 중인 판에 살아 있지 않을 때만 돼요.
- **계정을 정지하면** 바로 로그아웃되고 방에서 빠지며, 다시 로그인할 수 없어요.
- **비밀번호**는 scrypt로 해시해서 저장하고, 원문은 저장하지 않아요. 로그인은 30일 동안 유지돼요.
- **방 자체는 메모리에만** 있어서 서버가 재시작하면 사라져요. 계정과 칩은 DB에 남아요.

## 한계와 다음 단계
- 비밀번호 찾기 기능은 없어요. 필요하면 관리자가 DB에서 직접 처리해야 해요.
- Neon 무료 플랜은 쓰지 않으면 쉬다가 다음 요청에 다시 깨어나요. 첫 로그인이 아주 살짝 느릴 수 있어요.
- 소셜 로그인(카카오·구글)은 OAuth 앱 등록이 필요해서 넣지 않았어요.
